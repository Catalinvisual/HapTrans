# HAP CARGO — Database Conventions

> All future schema work MUST follow these conventions (TASK 03 §9).

## Storage
- Engine: **PostgreSQL 16**.
- All instants: `timestamptz(3)` storing **UTC**.
- Date-only values: `date`.
- Monetary values: `numeric` (Prisma `Decimal`), integer minor-unit `Money`
  abstraction at the app layer (ADR-022). **Never** use `float`/`double` for money.

## Naming
- Tables: **snake_case**, plural (`companies`, `audit_logs`).
- Columns: **snake_case**; index names generated by Prisma.
- Prisma field names: camelCase; use `@map`/`@@map` to snake_case at the DB.
- Relationships: `companyId`, `parentId`, `orderId`, etc. (camelCase → `company_id`).

## Identifiers
- Primary keys: `String @db.Uuid @default(uuid())` (UUID v4 public id).
- Never expose sequential DB ids as public identifiers.

## Timestamps
- Every table that represents a persistent record gets:
  - `created_at` — `@default(now())`
  - `updated_at` — `@updatedAt`
- `created_by`/`updated_by` are added where actor attribution matters.

## Tenant / multi-tenancy
- Every tenant-scoped table has a required `company_id` FK to `companies`.
- Tenant isolation is enforced **server-side** at the query layer — never by
  frontend filtering.
- Reference/master data may be shared; tenant data must always scope by company.

## Soft deletion
- Where "recoverable"/history preservation matters, use a nullable
  `deleted_at` timestamp.
- **Never physically delete** financial or audit records merely because a user
  clicks Delete.
- Lifecycle states are explicit (active/inactive, archived, cancelled,
  soft-deleted) rather than overloaded.

## Status / enums
- Statuses are **enums** (Prisma `enum`), never arbitrary free text.
- Stateful entities record **status history** for audit (see Audit).

## Audit
- Critical mutations append to `audit_logs` (actor, timestamp, company,
  entity, action, before/after, reason, request_id).
- Audit rows are append-only and never deleted.

## Indexes
- Every `company_id` + `status` + `created_at` combination that powers a
  list/search gets a composite index.
- All FKs that are queried are indexed.
- Unique constraints where business identity demands (e.g. `company.code`).

## JSON fields
- Use `Json` (JSONB) only where structure is genuinely flexible (metadata,
  telematics payloads, saved-view definitions). Prefer relational columns for
  queryable business data.

## Money columns
- `Decimal @db.Decimal(18, 4)` recommended; always pair with a currency column.

## Migrations
- Create incremental migrations with Prisma Migrate (`db:migrate`).
- **Never** run destructive reset in production.
- Apply via `db:deploy` in CI/CD.
- Migrations must be backward-compatible where possible to permit rollback.
